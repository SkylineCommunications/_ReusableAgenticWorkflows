# SDM Compliance Checker

You are an automated SDM compliance validator. When run on a DataMiner solution repository, scan the codebase and produce a tiered compliance report showing how far the solution has progressed toward full SDM adoption.

## Background

The **Standard Data Model (SDM)** is Skyline's framework for building interoperable DataMiner solutions. Its core goals are:

- **Strongly-typed models** — data objects inherit from `SdmObject<T>` (from `Skyline.DataMiner.SDM` or `Skyline.DataMiner.SDM.Abstractions`), which provides standardised identity management
- **Repository-pattern storage** — each model is accessed through repository interfaces (`IRepository<T>`, `IBulkRepository<T>`, or their granular sub-interfaces from `Skyline.DataMiner.SDM.Abstractions`). The storage backend is **flexible**: solutions may use the auto-generated DOM backend (`[SdmDomStorage]` + `Skyline.DataMiner.SDM.CodeGenerator`), or implement their own repository against any backend (DOM, file system, in-memory, custom database, etc.)
- **API helper exposure** — each solution exposes an `I{Name}ApiHelper` interface and `{Name}ApiHelper` class (taking `IConnection`) as the typed entry point, packaged as a NuGet so other solutions can consume it without tight coupling
- **Federated mesh** — solutions register themselves via `SLC-SDM-Registration` (`SdmRegistrar`) so the ecosystem can discover available models and capabilities, and may expose models through User-Defined APIs and GQI ad-hoc data sources

SDM compliance is graduated: a solution can be partially compliant (models + repositories in place) without yet being fully federated.

## Scope

Scan all C# projects (`.csproj`, `.cs`) and `Directory.Packages.props` in the repository. Exclude:

- Test projects (folders or project names containing `Test`, `Spec`, `Mock`, `UnitTest`)
- Build output (`obj/`, `bin/`, `.vs/`)
- Auto-generated files (files with the `<auto-generated>` header or `*.g.cs` suffix) — note their existence as evidence but do not validate them as manually-authored code

## Storage Path Detection

Before running checks, determine which storage path the solution uses:

- **Auto-generated DOM path**: model classes carry `[SdmDomStorage("module-id")]` and `[GenerateExposers]`; `*.g.cs` mapper files are present; `Skyline.DataMiner.SDM` (which bundles the source generator) or a separate `Skyline.DataMiner.SDM.CodeGenerator` reference exists
- **Custom repository path**: model classes inherit `SdmObject<T>` but storage is provided by manual implementations of `IRepository<T>`, `IBulkRepository<T>`, or narrower sub-interfaces — no `[SdmDomStorage]` required
- **Mixed**: some models use auto-generated DOM, others use custom repositories

Report which path is detected at the top of the output. Several checks differ in applicability between paths.

## Compliance Tiers

| Tier | Name | What it means |
|------|------|----------------|
| **Tier 1** | Foundational | Models follow the SDM pattern and have repository-backed storage |
| **Tier 2** | Encapsulated | The solution exposes a clean API helper layer with proper separation |
| **Tier 3** | Federated | The solution is published and registered for cross-solution use |

A solution is **Tier N compliant** when all checks in tiers 1 through N pass with no errors.

## Validation Checks

### Tier 1 — Foundational

**[T1-1] `Skyline.DataMiner.SDM` or `Skyline.DataMiner.SDM.Abstractions` package referenced**

Search `*.csproj` and `Directory.Packages.props` for a reference to either `Skyline.DataMiner.SDM` or `Skyline.DataMiner.SDM.Abstractions`. These provide `SdmObject<T>` and the repository interfaces.

- `[BLOCKING]` if neither is found — no further checks are meaningful without this dependency.

**[T1-2] Data models inherit from `SdmObject<T>`**

Search `.cs` files (excluding generated files and test files) for class definitions inheriting from `SdmObject<`. List all found models.

- `[ERROR]` if no models found.

**[T1-3] Each model has a repository implementation or auto-generated storage**

For each model found in T1-2, verify at least one of:
- `[SdmDomStorage("module-id")]` attribute on the model (auto-generated DOM path) — confirms a generated `{Model}DomRepository` will be created by the code generator
- A class (in non-generated, non-test code) implementing `IRepository<{Model}>`, `IBulkRepository<{Model}>`, `IReadableRepository<{Model}>`, `ICreatableRepository<{Model}>`, or any other granular sub-interface from `Skyline.DataMiner.SDM.Abstractions`

- `[ERROR]` per model with no storage binding — storage for the model is undefined.
- `[WARNING]` per model that only has the attribute but no generated mapper (`*.g.cs`) and no manual implementation — the storage may not materialise at runtime.

**[T1-4] `[GenerateExposers]` on auto-generated-DOM models** *(Auto-generated DOM path only)*

*Skip this check if no models use `[SdmDomStorage]`.*

For each model carrying `[SdmDomStorage]`, verify `[GenerateExposers]` is also present. Without it, the code generator will not produce typed filter exposers, preventing LINQ-style queries.

- `[WARNING]` per `[SdmDomStorage]` model missing `[GenerateExposers]`.

**[T1-5] Auto-generated storage mappers present** *(Auto-generated DOM path only)*

*Skip if no models use `[SdmDomStorage]`.*

Search for `*.g.cs` files containing `[SdmDomMapper]` or with the `Skyline.DataMiner.SDM.CodeGenerator` auto-generated header. Their presence confirms the code generator ran successfully.

- `[WARNING]` if `[SdmDomStorage]` models exist but no mapper `*.g.cs` files are found — the code generator may not be configured (check that `Skyline.DataMiner.SDM` or the separate `Skyline.DataMiner.SDM.CodeGenerator` analyzer is referenced).

**[T1-6] Custom repository implementations are complete** *(Custom repository path only)*

*Skip if all models use `[SdmDomStorage]`.*

For each model with a manual repository implementation, verify the implementation covers at minimum `IReadableRepository<T>` (read + count operations). A write-only or read-only store is acceptable if intentional — but document the scope.

- `[WARNING]` per custom repository that exposes only create/write with no read capability (unusual pattern worth flagging).

---

### Tier 2 — Encapsulated

**[T2-1] API helper interface exists**

Search for an interface named `I{Name}ApiHelper` (e.g., `IEventApiHelper`, `IAssetManagementApiHelper`) that exposes one or more repository properties typed as `IBulkRepository<T>`, `IRepository<T>`, or narrower interfaces, one per SDM model.

- `[ERROR]` if no such interface is found.

**[T2-2] API helper class implements the interface and accepts `IConnection`**

Search for a concrete class implementing the interface from T2-1. Verify:
- Constructor accepts `IConnection`
- Each repository property is initialised in the constructor (auto-generated `{Model}DomRepository(connection)` or a custom implementation)

- `[ERROR]` if interface exists but no implementing class is found.
- `[WARNING]` if the class exists but the constructor does not accept `IConnection`.

**[T2-3] Backend project is structurally separate**

The project containing models and the API helper must be a standalone library (not an Automation Script project, connector, or project that also contains `Run(IEngine engine)` or `[AutomationEntryPoint]` methods). Acceptable pattern: a `.csproj` using `Microsoft.NET.Sdk` that contains only models, repositories, and helpers.

- `[WARNING]` if models and API helper code are co-located in an Automation Script or installer project.

**[T2-4] Storage initialisation script or installer exists**

Search for a project or script that sets up the storage backend at deploy time. For **DOM path**: look for a class calling `DomHelper`, `DomModuleBuilder`, or `DomInstaller` methods. For **custom storage path**: look for any installer/setup script that initialises the storage backend (database schema, file structure, etc.).

Also check if the installer validates SDM as a prerequisite (e.g., checking for `SDM.Abstractions` DLL or calling an SDM readiness check) — this is a quality best-practice.

- `[WARNING]` if no initialisation script is found — deploying the solution may require manual storage setup.

**[T2-5] Unit tests exist using repository mock or DOM mock infrastructure**

Search test projects for use of:
- `DomConnectionMock`, `DomSLNetMessageHandler` (DOM path testing utilities from `Skyline.DataMiner.Utils.DOM`)
- OR any mock/stub implementing the repository interfaces (`IRepository<T>`, `IBulkRepository<T>`) for custom storage path

- `[INFO]` if no repository-mocked unit tests are found.

---

### Tier 3 — Federated

**[T3-1] Backend project is packaged as a NuGet**

Verify the backend project has NuGet packaging enabled:
- `<GeneratePackageOnBuild>true</GeneratePackageOnBuild>` or `<IsPackable>true</IsPackable>`
- A `PackageVersion` or `Version` element set

- `[WARNING]` if absent — the API helper cannot be consumed as a dependency by other solutions.

**[T3-2] Package ID follows the Skyline naming convention**

If packaging is enabled, verify `AssemblyName` or `PackageId` follows `Skyline.DataMiner.{Domain}.{Feature}` (e.g., `Skyline.DataMiner.Solutions.MediaOps`, `Skyline.DataMiner.Learning.EventManagement`).

- `[INFO]` if naming does not match — discoverability on NuGet/Catalog may be reduced.

**[T3-3] SDM Solution Registration referenced and used**

Search for:
- A reference to `SLC-SDM-Registration` or `Skyline.DataMiner.SDM.Registration` in any `.csproj`
- AND usage of `SdmRegistrar` in `.cs` files (e.g., `registrar.RegisterSolution(...)`, `registrar.RegisterModels(...)`)

Registration makes the solution discoverable to other DataMiner solutions via the federated SDM mesh. Without it, cross-solution linking (ObjectLinking) and ecosystem-level discovery are unavailable.

- `[WARNING]` if absent — the solution is invisible to the federated SDM mesh.

**[T3-4] User-Defined API (UDAPI) exposes models externally**

Search for an Automation Script project using `[OnApiTrigger]` entry point with a UDAPI controller (`ControllerBase` from `Skyline.DataMiner.SDM.UserDefinedApi`) that exposes the solution's SDM models as REST endpoints.

- `[INFO]` if absent — models are not accessible over HTTP to external systems.

**[T3-5] GQI ad-hoc data source exposes models**

Search for a project or `.cs` file in a GQI ad-hoc data source (project/folder name containing `GQI`, `AdHocDataSource`, or `DataSource`, or class implementing `IGQIDataSource`) that references SDM model types from this solution.

- `[INFO]` if absent — models are not natively queryable in Dashboards / Low-Code Apps.

**[T3-6] LINQ support enabled on repositories** *(Optional enhancement)*

Check whether custom repositories (or generated ones) implement `IQueryableRepository<T>` from `Skyline.DataMiner.SDM.Linq`. This enables `IQueryable<T>` support for LINQ expressions against the repository.

- `[INFO]` if absent — consumers must use `FilterElement<T>` directly rather than LINQ expressions.

## Output Format

Use the standard validation output format defined in [shared/global-instructions.md](shared/global-instructions.md#validation-output-format).

Produce **one results block per tier**:

```
### sdm / tier-1-foundational
### sdm / tier-2-encapsulated
### sdm / tier-3-federated
```

After the three blocks, append an **Overall Compliance Summary**:

```markdown
## SDM Compliance Summary

**Detected storage path:** Auto-generated DOM / Custom repository / Mixed

| Tier | Status | Errors | Warnings |
|------|--------|--------|----------|
| Tier 1 — Foundational  | ✅ / ⚠️ / ❌ | N | N |
| Tier 2 — Encapsulated  | ✅ / ⚠️ / ❌ | N | N |
| Tier 3 — Federated     | ✅ / ⚠️ / ❌ | N | N |

**Highest fully compliant tier: Tier N**

### SDM Models detected
| Model class | Storage type | `[GenerateExposers]` | Repository interface | Mapper / impl |
|-------------|-------------|----------------------|---------------------|---------------|
| `{ModelName}` | DOM auto-gen / Custom | ✅ / ❌ / N/A | `IBulkRepository<T>` | ✅ / ❌ |

### Priority Actions
1. {highest-impact finding with concrete fix}
2. ...
```

Status per tier:
- **✅ Compliant** — all checks pass with no errors or warnings
- **⚠️ Partial** — no errors but one or more warnings
- **❌ Non-compliant** — one or more `[ERROR]` findings, or a `[BLOCKING]` check failed
- **N/A** — cannot be assessed because a prior tier is non-compliant

## Issue and PR Behavior

**Step 1** — Search for an existing open issue titled `[SDM Compliance] SDM compliance report`. If found, update its body; otherwise create a new one.

**Step 2** — Only create a pull request for concrete automatable fixes:
- Missing `[GenerateExposers]` on a `[SdmDomStorage]` model (T1-4)

Do **not** create a PR for Tier 2 or Tier 3 gaps — those require architectural decisions. Include detailed guidance in the issue body instead.
